# 0081 — Post-audit dead-weight retirements: /qa-review, /glossary + glossary-critic, critic golden-set evals, /build

Status: Accepted
Date: 2026-08-21

**Supersedes (per-decision):** ADR-0040 D4 (the `/qa-review` clearing skill — the skill retires; ADR-0040 D1/D2/D3/D5 STAND: the empirical-residual model, the async non-blocking `needs-human-check` queue, the one-headline rule, and browser-route fidelity are all untouched), ADR-0038 D3 (the consolidated `/glossary` skill with `add`|`fold` subcommands — both subcommands retire; ADR-0038 D1/D2 — the skill-vs-agent litmus and the skills-dispatch-subagents topology — STAND), ADR-0007 D5 (the `glossary-critic` subagent — retired; ADR-0007 D2/D3 — entry shape and the three-category scope rule — STAND as the glossary's content contract), ADR-0012 D3 (the `/glossary-add` skill simplification — moot with the skill retired), ADR-0012 D4 (the glossary-critic rubric update — moot with the critic retired), ADR-0012 D5 (PARTIAL — only its "`glossary-critic` is the bouncer per D4" enforcement clause; the ~35-entry soft cap itself STANDS, mechanically checked by the existing DOCS-9 health row), ADR-0067 D5 (golden-set critic evals — `tools/run_evals.py` + `tests/evals/` retire; ADR-0067 D1/D2/D3/D4 — the tests/ suite in CI, R-PROVE, the rule-#13 rider, and the flaky quarantine — STAND untouched), ADR-0034 D1 (the separate `/build` orchestrator skill — retired; its non-duplicated steps fold into `/ship`), ADR-0034 D2 (PARTIAL — only its "`/build` is the convenience conductor layered on top" clause; the sub-skills-remain-atomic-and-individually-invocable principle STANDS for `/grill-me` and `/qa-plan`). **Extends:** ADR-0034 D3 (the grill-conditional auto-assess-announce-proceed procedure is preserved VERBATIM and rehosted in `/ship` — an extension/relocation, not a supersession), ADR-0034 D4/D5/D7 (README-as-build-artifact, R-DOCS-CURRENT, and the doc-generator all SURVIVE untouched — this is why ADR-0034 as a whole must remain in the active frontmatter set: it still sources DOC-001/DOC-002), ADR-0046 D1 (the critic-parsimony principle — applied here in reverse: a critic whose concern no longer earns a dedicated gate is removed, 7→6), ADR-0004 D2 (bootstrap-mode).

**Bootstrap-mode (ADR-0004 D2):** binds forward from the implementing PRD's slices. No retroactive sweep: closed `needs-human-check` issues, past glossary entries (all grandfathered content stays), the one historical eval run, and past `/build` invocations in logs/evidence are history, not violations.

## Context

The 2026-08-20 full-component audit measured every workflow component against its purpose; the operator approved ALL recommendations via checkpoint (2026-08-20, sibling of the ADR-0080 frontend ruling). Four mechanisms were flagged as dead weight, each needing a small ADR supersession:

1. **`/qa-review`** (ADR-0040 D4) — the dedicated `needs-human-check` clearing skill. The operator now clears residuals through the personal, out-of-repo decide-flow (Decision Inbox cards) plus plain `gh issue list --label needs-human-check`. Usage evidence: exactly one organic `skill_invoke(qa-review)` in the archived event corpus (2026-06-10-era forensics, `qa-proof/forensics/topology-ontologist.md`); the AskUserQuestion-card procedure it wraps has been superseded in practice by the decide-flow's richer card UX. The residual QUEUE is load-bearing and survives in full.
2. **`/glossary` + `glossary-critic`** (ADR-0038 D3 host; critic per ADR-0007 D5 as updated by ADR-0012 D4). The glossary CONTENT (CLAUDE.md §4) is load-bearing and survives; the dedicated add/fold skill and its critic are ceremony around what is, since ADR-0012 D1, a one-file Markdown edit. Per the ADR-0046 D1 parsimony principle (PIP-011), a critic must earn its place against a distinct concern — a CLAUDE.md §4 diff is a concern the `reviewer` already absorbs on every PR. Critic count: 7 → 6.
3. **Critic golden-set evals** (ADR-0067 D5) — `tools/run_evals.py` + `tests/evals/` (3 `manifest.json` files + **27** fixture files — 9 cases per critic across reviewer/prd-critic/slicer-critic, matching each manifest's 9 case entries; counted live at origin/main c54a92e). Honest usage record: ONE recorded run since seeding — a slicer-critic smoke run on 2026-06-16 (local, gitignored `tests/evals/results.json`, pass_rate 1.0) — and zero runs since, across a period in which critic prompts changed repeatedly. The three EVAL-* health rows have reported the honest no-baseline/stale WARN bucket ever since. The instrument's stated purpose (before/after measurement on critic-prompt changes, the model-tiering evidence precondition) was never exercised; ADR-0071 D2 already retired the fleet-economics machinery the evals were feeding. The `tests/` suite, CI wiring, R-PROVE, and quarantine (ADR-0067 D1–D4) are actively load-bearing and survive untouched.
4. **`/build`** (ADR-0034 D1) — the full-lifecycle thin conductor. Verified against both SKILL bodies at origin/main c54a92e: of `/build`'s six steps, three are byte-duplicated in `/ship` (step 0 live-feed self-check ≡ `/ship` step 0; step 3's ship call IS `/ship`; step 5's production-verify gate ≡ `/ship` step 6 including the ADR-0061 validations, proof-posting, and SendUserFile blocks — ~120 lines maintained twice), and three exist only in `/build` (step 1 dashboard-check, step 2 grill-conditional auto-assess, step 4 regenerate-docs). Maintaining the duplicated gate twice has already produced drift (the CLAUDE.md Map row and `pipeline_spec.py` still describe `/build`'s tail as "`/qa-plan`" while the body dispatches `qa-tester` directly). The three `/build`-only steps fold into `/ship`; the `invoked_by: build` dedup machinery dies with the wrapper. The README-generator machinery (ADR-0034 D4/D5/D7) is unrelated to the conductor and survives untouched.

## Decisions

### D1 — `/qa-review` is retired; the residual queue and its semantics survive

`.claude/skills/qa-review/SKILL.md` is deleted. The `needs-human-check` label, the PROVISIONAL-is-the-residual signal, the async non-blocking queue, and machine-PASS-alone PRD auto-close (ADR-0040 D1/D2/D3/D5) all STAND — `/qa-plan` keeps posting residuals exactly as today. **Where the clearing duty goes:** the operator clears the queue on their own cadence via the decide-flow (personal, out-of-repo Decision Inbox) and/or plain `gh issue list --label needs-human-check --state open`; accept→`gh issue close --reason completed`, reject→relabel `captured` + rule-#13 capture — the same verdict-recording protocol the skill scripted, now operator-driven `(advisory — the clearing procedure lives outside the repo and cannot carry an in-repo check; the QUEUE's health remains observable via the existing RESIDUAL-RATIO health row, which is the deterministic survivor)`. ADR-0040 D4's "refined, not removed" human-checkpoint lineage (ADR-0020 D10 → ADR-0040 D4 → this) continues: the checkpoint moves host a second time, from a repo skill to the operator's decide-flow.

**Enforcement (rule #23):** deletion is the check's subject — grep count=0 for `qa-review`/`qa_review` across the runtime surface (CLAUDE.md, `.claude/`, `dashboard/`, `tools/`, `bootstrap.sh`, `README.template.md` + regenerated `README.md`; `decisions/` archive and `qa-proof/` evidence excepted); `gh label list` still contains `needs-human-check`; RESIDUAL-RATIO stays registered. No new convention is introduced (the replacement is an already-existing operator practice, tagged advisory above). **Shadow guarded against (ADR-0056 D2c):** *silent residual-queue starvation with no visible clearing signal* — residuals piling up unread because the clearing duty moved out of the repo and nothing in the repo reports on it. The RESIDUAL-RATIO health row is the surviving deterministic instrument that makes this shadow visible if it re-appears; a future audit tests the shadow by reading that row's open/cleared ratio, not by looking for the skill.

### D2 — `/glossary` and `glossary-critic` are retired; the glossary and its content contract survive; critic count 7 → 6

`.claude/skills/glossary/SKILL.md` (both `add` and `fold` subcommands) and `.claude/agents/glossary-critic.md` are deleted. The glossary itself — CLAUDE.md §4, single-tier per ADR-0012 D1 (GLO-003), entry shape per ADR-0007 D2 (GLO-001), scope categories per ADR-0007 D3 (GLO-002) — SURVIVES untouched.

**Replacement mechanism (named, not silent):** glossary edits ride **normal reviewer-gated PRs**, like any other CLAUDE.md edit. The rule #10 pipeline (PRD/slice/trivial-lane) and the `reviewer` critic are the gate; per ADR-0056 D4, a critic rubric IS a deterministic-enough mechanism, so this is not an enforcement downgrade to prose.

**Per-duty disposition of what glossary-critic uniquely enforced:**
- **~35-entry soft cap (GLO-004 / ADR-0012 D5):** already mechanized independently of the critic by the **DOCS-9 health row** (`check_docs9_glossary_cap`, WARN at >35) — the cap survives with a deterministic checker; the "bouncer" clause of ADR-0012 D5 is the only part superseded.
- **Entry-shape and dangling-authority hygiene:** DOCS-6 (no stale GLOSSARY.md refs) and CHECK 4 (dangling ADR-citation gate, which scans all tracked prose including CLAUDE.md §4's parenthetical ADR cites) remain as deterministic checks; the reviewer judges shape on the diff.
- **The 5-rule adversarial rubric as a dedicated pre-PR gate** — scope-category fit, duplicate hunt, one-sentence discipline, authority resolvability, and ADR-0012 D2's ≥3-citations-across-≥2-directories threshold as a hard mechanical gate — is an **accepted loss**, listed in Consequences. The threshold survives as reviewer guidance (the grep is one command), not as an automated BLOCK.

**Parsimony (ADR-0046 D1 / PIP-011):** the principle cuts both ways; a critic whose distinct concern has collapsed into an existing critic's ordinary purview is removed rather than maintained. The critic roster becomes: `reviewer`, `prd-critic`, `adr-critic`, `slicer-critic`, `backlog-critic`, `codebase-critic` (6).

**Enforcement (rule #23):** CHECK 7 (doc-vs-reality drift gate) is the natural enforcer — it cross-checks `dashboard/server.py` `KNOWN_CRITICS` ↔ `.claude/agents/*.md` ↔ CLAUDE.md critic prose ↔ README critic list, so the 7→6 change must land consistently in all four places or CI fails; grep count=0 for `glossary-critic`/`glossary_critic` across the runtime surface (same exclusions as D1); DOCS-9 stays registered and PASS/WARN-capable. The skill/critic return only via a new ADR that re-argues parsimony. **Shadow guarded against (ADR-0056 D2c):** *glossary scope-creep re-accumulating with no adversarial check* — entries drifting past the ~35 soft cap, or outside ADR-0007 D3's three inclusion categories, with nothing objecting because the objector was deleted. DOCS-9 (cap, deterministic) plus the `reviewer`'s ordinary CLAUDE.md-diff purview are the instruments a future audit tests the shadow against; if leaked entries actually appear, the Alternatives section's R-GLOSSARY reviewer rule is the pre-argued response.

### D3 — Critic golden-set evals are retired; the regression suite is untouched

`tools/run_evals.py`, `tests/evals/` (fixtures + manifests; the gitignored local `results.json` simply stops accumulating), and the three EVAL-* health rows (`EVAL-REVIEWER`, `EVAL-PRD-CRITIC`, `EVAL-SLICER-CRITIC`) are deleted — the check registry shrinks **53 → 50** (re-derived live at origin/main c54a92e: `python dashboard/health.py --list | wc -l` = 53, of which 3 are EVAL-*; independently corroborated by ADR-0080 D1's own prose, which names "the 53-check registry" as untouched by that ADR). Same re-derivation escape-hatch as the rules baseline: **the invariant is the −3 EVAL-* delta; the absolute pair is re-derived at implementation time** from `--list`, since another PRD may add or remove a row before this one lands. Subject tests die WITH their subjects, never orphan-skipped (the ADR-0080 D1(d) discipline): `tests/test_eval_runner.py` and `tests/test_run_evals_utf8_834.py` are deleted whole (their subjects are gone; the #834 utf-8 bug class remains regression-guarded by the surviving sibling `tests/test_slicer_provenance_utf8_1050.py`); `tests/test_data_state_classifier_967.py` drops its EVAL-detail patterns; `tests/test_loc_cap_1162.py` drops its `TestEvalFixtures` class (its fixture subjects die). The `.gitignore` `tests/evals/results.json` line and the hardcoded `run_evals.py` row in `tools/gen_repo_map.py` are pruned.

**Zero-consumer proof:** consumers of `tests/evals/`/`results.json` at origin/main c54a92e are exactly {the runner itself, the three health rows, the four test files above, two doc rows (CLAUDE.md Map, `_repo-map.md`), the REG-003 rule statement} — all dispositioned in Propagation; nothing else reads the fixtures or results. The only recorded run ever is the 2026-06-16 seeding-time slicer-critic smoke run; no CI stage, skill, or agent invokes the runner (ADR-0067 D5 made it on-demand-only, and the demand never came).

**What explicitly survives:** ADR-0067 D1 (tests/ in CI — REG-001), D2 (R-PROVE — REG-002), D3 (rule-#13 rider), D4 (quarantine + SLA — the surviving half of REG-003). **Return trigger (checkable):** golden-set evals return only via a new ADR, gated on a `captured` issue documenting a concrete critic-prompt regression that shipped a bad verdict and would have been caught by a before/after eval — the failure mode ADR-0067 D5 hypothesized but never observed.

**Enforcement (rule #23):** `python dashboard/health.py --list` no longer prints the three EVAL-* ids; grep count=0 for `run_evals`/`tests/evals` across the runtime surface (same exclusions; the two historical bug-class code comments named in Propagation are the enumerated exceptions); `pytest tests/` green with the subject tests deleted. **Shadow guarded against (ADR-0056 D2c):** *a critic-prompt regression that ships a bad verdict undetected* — a prompt edit silently degrading a critic's judgment with no before/after measurement to catch it. This is the same failure the return trigger above is written to detect, stated here as the shadow: a future audit tests it by asking whether any `captured` issue documents that concrete regression, and the standing downstream instruments (MERGED-WITHOUT-VERDICT, CRITIC-HEALTH, reviewer BLOCK/APPROVE outcomes) are the residual detectors that remain.

### D4 — `/build` merges into `/ship`; `/ship` is the single lifecycle orchestrator

`.claude/skills/build/SKILL.md` is deleted. `/ship` absorbs the three steps `/build` had that `/ship` lacked (delta verified line-by-line at origin/main c54a92e, per the Context table):

1. **Dashboard-check** (idempotent `dashboard-autostart.sh` invocation, ADR-0034 D1 step 1) — becomes a `/ship` pre-step alongside its existing step 0. It stays soft-fail and observability-only; SessionStart also autostarts per ADR-0033, this is the orchestrator-coupled second trigger, unchanged in mechanism.
2. **Grill-conditional auto-assess** (ADR-0034 D3, rehosted, not superseded) — `/ship` step 1's "confirm grilled context" gains the full D3 procedure: judge input concreteness, announce the call, invoke `/grill-me` when vague, proceed without a blocking confirmation when concrete. `/grill-me` remains standalone (ADR-0034 D2's surviving clause).
3. **Regenerate-docs** (`python dashboard/server.py --generate-readme`, ADR-0034 D1 step 4) — becomes a `/ship` post-merge step before the production-verify gate. Soft error as today; R-DOCS-CURRENT (ADR-0034 D5) remains the hard gate.

Dies with the wrapper: the duplicated production-verify gate text (one copy remains, in `/ship` step 6), the `invoked_by: build` dedup rule and the `PRODUCTION_VERIFY: skipped-nested` trailer value (no nesting exists anymore), the `/build` GENERATOR trailer, and the `build` node + edges in `dashboard/pipeline_spec.py`. CLAUDE.md rules #15 and #20 reroute their step pointers to `/ship` (rule numbers untouched per DOC-003). The ADR-0034 D4/D5/D6/D7 README-generator machinery is byte-untouched.

**Enforcement (rule #23):** grep count=0 for `.claude/skills/build/`, `invoked_by: build`, and `skipped-nested` across the runtime surface; grep ≥1 in `ship/SKILL.md` for each absorbed step's named anchor (dashboard-autostart invocation, the ADR-0034 D3 announce strings, the `--generate-readme` call); the qa-tester production-verify route (VER-001, PROOF-PRESENCE row) keeps `/ship` step 6 as its single dispatch site. `/build` returns only via a new ADR demonstrating a conductor concern `/ship` cannot host. **Shadow guarded against (ADR-0056 D2c):** *duplicated gate-prose drift* — the same gate maintained in two SKILL bodies until the copies quietly disagree. This shadow is not hypothetical: Context §4 records it already materialized (the CLAUDE.md Map row and `pipeline_spec.py` still advertise a `/qa-plan` tail that `/build`'s body dropped). Naming it here makes the test cheap for a future audit — one gate body, one grep site; if a second copy of the production-verify gate text ever re-appears in any SKILL.md, the shadow is back.

## Alternatives considered

- **Keep `/qa-review` as a thin wrapper over the decide-flow:** rejected — a tracked skill whose body says "go use an untracked skill" is indirection, not function; the queue (the load-bearing part) needs no wrapper.
- **Extend `reviewer` with an explicit R-GLOSSARY rule instead of relying on ordinary review:** rejected for now — ADR-0007's own Alt-D rejected exactly this in the opposite direction when glossary volume justified a dedicated critic; today's volume (soft cap never hit, additions rare) justifies neither a critic nor a bespoke reviewer rule. DOCS-9/DOCS-6/CHECK 4 are the deterministic floor; a future ADR can add R-GLOSSARY if leaked entries actually appear.
- **Keep `tests/evals/` fixtures but delete only the runner:** rejected — consumer-less fixtures are exactly the dead weight class this ADR retires; the fixtures are one `git revert` away if the D3 return trigger ever fires.
- **Fold `/ship` into `/build` (keep the outer name):** rejected — `/ship` is the name every ADR, hook, verb, and habit references (ADR-0003 D7 lineage); the wrapper, not the pipeline, is the dead weight.
- **Whole-ADR supersessions (0040/0012/0034/0067) instead of per-decision:** rejected — each target ADR still sources live rules (VER-004..006, GLO-003/004, DOC-001/002, REG-001..003); whole-ADR supersession would silently drop them from `_global.md` via gen_rules' whole-ADR exclusion. The per-decision form plus statement amendments is the only shape that conserves the surviving rules.
- **One ADR per retirement (four small ADRs):** rejected — one audit, one operator checkpoint, one propagation sweep, one rules-bundle; four ADRs would quadruple the index/README/regen ceremony for the same decision record. The per-decision supersedes list keeps granular machine-readability.
